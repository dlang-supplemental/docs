== Versioning

[cols="1,3"]
|===
| 0.1.0 (current code)
| Per-thread private heaps, local collect without global `thread_suspendAll`, remote-free stub.
  **No working partitioned shared regions yet.**
| Target (post-0.1.0)
| Many-to-many **partitioned shared regions**, region-scoped STW, selective thread suspend.
|===

== Problem statement

D isolates *data* by default (TLS, actor-style `std.concurrency`) but the default GC uses one process-wide heap.
Any collection can stop-the-world pause every registered thread, including `@nogc` realtime workers that never allocate.

The goal is **pause isolation**: threads that do not depend on the same GC data should not pause each other.

== Target architecture (the actual design)

=== Per-thread private heap

Every attached thread owns a private arena.
Collection scans only that thread’s stack, TLS, roots, and blocks in its private heap.
No global STW for a pure local collect.

=== Partitioned shared regions (core cross-thread model)

Cross-thread data is **not** modeled as “copy everything” or “remote free on the owning thread’s private heap.”
Those are interim or escape-hatch paths only.

The intended model is **partitioned shared regions**:

* A region is a GC heap shared by an explicit set of threads (many-to-many).
* Threads opt in to regions that match their *data dependency* and *lifetime*.
* Collecting region *Alpha* pauses **only threads attached to Alpha**, not the whole process.
* A thread with only a private heap and no shared regions is never paused by another region’s collection.

Example:

* Worker 1: private heap + Region Alpha + Region Beta
* Worker 2: private heap only (never paused by Beta)
* Worker 3: private heap + Region Alpha

A 4K frame ring between decode workers lives in a **deliberate shared region**, not in one thread’s private heap with copies or remote frees.

[NOTE]
====
**Partitioned shared region** here means: threads that depend on the same data share one STW event for *that region*, not that the whole process shares one heap.
====

=== `@nogc` / detach

Threads that call `thread_detachThis()` remain outside all GC pauses.
They must never touch GC memory.

== What 0.1.0 actually ships

The upstream PR branch implements only the **private per-thread heap** slice:

* `--DRT-gcopt=gc:tgc`
* Local collect on the calling thread
* Remote free list (ownership return to allocating thread’s private heap) — **interim**, not the target cross-thread story
* Shared-region API scaffold (`create` / `attach` / `allocInRegion`) — **structures only**; region collect and selective suspend are not done

Do not treat 0.1.0 as feature-complete or as endorsing copy-first messaging.

== Pluggable GC and SymGC

druntime selects **one** GC implementation at process startup (`--DRT-gcopt=gc:…`).
`createGCInstance` installs a single factory; there is no supported API today to call SymGC (`gc:sdc`) on one branch and `tgc` on another inside the same process.

SymGC and `tgc` are **complementary at the ecosystem level**:

* SymGC: modern **shared** heap, less global lock contention.
* `tgc`: **pause isolation** via private heaps and region-scoped STW.

Future work could add a composite GC or explicit region handles; that is not in 0.1.0.

Practical split today: different processes, or default/SymGC for most of the app plus `@nogc`/manual islands — not mixed pluggable backends per branch.

== Transitive pause risk (honest limit)

If Worker 1 shares Alpha with Worker 3, and Worker 3 shares Beta with Worker 2, a Beta collection that pauses Worker 3 can stall Worker 1 when Worker 1 needs Alpha.
Preventing cascades needs a DAG of region membership at the API or type level — future work.
